# Doubao Original Media Helper 2.3.2

这是图片与视频功能合并后的测试版。图片链路保持原有实现，视频链路加入同一个扩展、同一个 Popup、同一个会话分类和缓存管理。

2.3.2 在保持当前会话过滤的基础上优化了网页与 Popup 性能：网页只响应媒体 DOM 变化，Fiber 扫描延后并缩小遍历范围；Popup 使用分批渲染和缩略图懒加载。网页面板只居中显示“加载成功”，整体最大高度为 320px。切换会话后的短时间内会识别尚未写入 `src` 的图片占位节点，不再依赖滚动触发豆包懒加载。图片记录必须包含原图字段，视频封面不会再被误判为无水印图片。

## 本版能力

- 会话内图片、右侧大图和豆包原生图片下载使用无水印原图。
- Popup 同时显示无水印图片与无水印视频。
- 按“会话标题 - Chat ID”分类，可筛选全部媒体、图片或视频。
- 卡片底部单独勾选，支持单项下载、删除、全选和图片/视频混合批量下载。
- 视频预览前会刷新临时地址；下载失败自动重试，并按每个视频选择最高画质。
- 图片与视频历史保存在 IndexedDB，只保存缩略图和元数据，不保存原始大文件。
- 图片与视频共用 50、100、250、500 MB 缓存上限，超限后删除最旧记录。
- IndexedDB 从 v3 升级到 v4，原有图片历史不会被主动清空。
- 豆包网页右上方自动出现当前页面媒体面板，可折叠、关闭、单项下载和按类型全部下载。
- 网页面板包含“图片 / 视频”Tab，仅显示本次页面加载后实际识别到的媒体；Popup 才负责完整历史。
- Popup 可切换“记录所有打开会话”或“仅当前会话”。

## 会话范围

插件不会请求并遍历豆包账号下所有历史对话。它支持：

1. 当前打开的会话。
2. 安装后新建并打开的会话。
3. 安装前的旧会话，在你重新打开或刷新后进行捕获。

因此，“全部会话”表示插件本机已经捕获过的全部会话，并不是豆包服务器上的全部对话。

## 升级安装

1. 先在 `chrome://extensions/` 禁用独立的“豆包视频去水印”插件及之前的 Video Debugger 测试插件。Chrome 同一标签页通常只能被一个 Debugger 客户端占用。
2. 克隆或解压本仓库到一个固定目录。
3. 打开 `chrome://extensions/`，开启“开发者模式”。
4. 如果已有本插件，点击“重新加载”；首次安装则点击“加载已解压的扩展程序”，选择仓库内的 **`doubaoparser`** 目录（内含 `manifest.json`）。
5. 确认扩展名称为 `豆包图片视频去水印`、版本为 `2.4.3`。
6. 关闭旧 Popup，回到豆包页面按 `Ctrl + Shift + R` 强制刷新。
7. 页面正中央应短暂出现「插件已就绪 · 数据仅在本地处理」。
8. 页内面板底部应为「支持作者」按钮。
9. 页面顶部出现“正在调试此浏览器”的提示属于视频监听的预期现象，请不要点“取消”。

如果提示数据库升级被阻塞，关闭所有该插件的 Popup 和豆包标签页，重新加载扩展后再试。

## 合并版测试顺序

### 0. 网页面板与捕获范围

1. 刷新豆包会话后，页面右上方应自动出现蓝色小面板，不需要先点击扩展图标；头部固定显示“加载成功”与绿色圆点。
2. 面板只显示当前页面本次加载后识别到的图片和视频，不读取该 Chat ID 的旧缓存，也不显示其他会话。
3. 分别点击“图片”和“视频”Tab，列表、数量和底部下载按钮应独立切换。
4. 直接点击左侧另一个会话（不刷新），面板应清空上一会话并通过 React Fiber 重新识别新会话当前页面里的图片。
5. 再强制刷新，新会话有 4 张生成图片时面板仍应显示 4 张，而不是初始化 JSON 中的全部历史候选。
6. 点击头部左侧圆角方块内的箭头可折叠，箭头方向会同步翻转；点击关闭后会保留一个蓝色圆形入口，可重新打开。
7. 单项“下载”和底部“下载全部图片/视频”都应只作用于当前 Tab。
8. Popup 中选择“仅当前会话”，再把另一个豆包标签页放到后台并刷新：后台标签不应新增历史；切换到该标签页后再次刷新，才应开始记录。
9. 切回“记录所有打开会话”，多个已经打开的豆包标签页都可继续捕获。

“仅当前会话”会随当前活动标签页变化，并不是永久锁死在开启按钮时的某个 Chat ID。已有历史不会因为切换模式而删除。

### 1. 图片回归

打开一个含有生成图片的会话并刷新，确认：

- 左侧会话图片无水印。
- 点击后的右侧大图无水印。
- 豆包页面原生下载按钮下载无水印图片。
- Popup 的图片卡片可下载，文件扩展名与真实格式一致。
- 页面图片上没有插件增加的勾选框。

### 2. 视频连接与捕获

1. 打开含有已生成视频的豆包会话并强制刷新。
2. 打开 Popup，视频状态应显示绿色“视频监听已连接”。
3. 等待该会话的聊天响应加载；Popup 中应出现视频卡片。
4. 如未出现，点击“重连视频”，然后再次刷新豆包会话。
5. 视频卡片应归入当前“会话标题 - Chat ID”，不会跑到其他会话。

### 3. 视频预览与下载

1. 点击视频卡片“预览”，应新开一个无水印视频地址。
2. 点击“下载”，在 `chrome://downloads/` 检查下载来源，应为 ByteDance/Douyin 视频域名，URL 通常含 `lr=unwatermarked`。
3. 播放下载的 MP4，确认无“豆包AI生成”水印。
4. 临时地址过期后再次点击预览或下载，插件应通过保存的 fallback API 自动刷新地址。

### 4. 会话历史

1. 在会话 A 捕获图片和视频。
2. 切换到会话 B 并捕获媒体。
3. Popup 默认定位当前会话；下拉框应同时出现 A、B，格式为“会话标题 - Chat ID”。
4. 关闭 Popup、刷新页面再打开，历史记录应仍然存在。
5. 旧对话只有在重新打开/刷新后才会加入，不会在后台扫描全部历史。

### 5. 筛选、选择与批量下载

- 切换“全部媒体 / 图片 / 视频”，数量和卡片应同步变化。
- 勾选框只在 Popup 卡片底部。
- “全选当前”只选择当前会话和当前媒体类型筛选结果。
- 同时选中图片和视频后点“批量下载”，两类任务应分别进入可靠下载队列。

### 6. 删除与缓存

- 卡片“删”只删除该条本地记录，不删除豆包内容或已下载文件。
- “删除分类”删除所选会话内的图片和视频本地记录。
- “清空全部”清空插件捕获的所有图片、视频历史。
- 缓存统计分别显示图片数、视频数；“立即整理”按捕获时间删除最旧媒体。

## 常见问题

### 视频监听连接不上

- 关闭当前豆包页的普通 F12 DevTools。
- 禁用其他使用 Chrome Debugger 的豆包视频扩展。
- 点击 Popup 的“重连视频”，再刷新会话。
- 在 `chrome://extensions/` 打开本扩展的 Service Worker 控制台，查看 `[Doubao Original Video]` 错误。

### 页面 Network 有视频但 Popup 没有

确认加载的是 `/im/chain/single` 响应，随后保持 Debugger 连接并刷新。插件只处理当前及之后监听到的响应，不回溯浏览器在连接前已经完成的 Network 请求。

### 隐私与日志

插件只在本机解析目标媒体接口，不上传聊天内容。排错截图不要公开 Cookie、Token、签名参数、完整私人对话或媒体临时地址。

## 当前边界

合并版先把已验证的视频捕获、最高画质解析、历史、预览和下载并入图片插件。视频暂不替换豆包会话中的原生播放器或原生视频下载按钮；确认本版稳定后，再单独做页面播放器替换，避免影响已经稳定的图片页面逻辑。
